Read subscribed IBKR quotes

Trader's broker connection window can inspect a streaming bid, ask and last price for one explicitly identified contract. It uses Framework's read-only connection to a local TWS or IB Gateway session. Its values are separate from the simulation chart and order-entry models.

Connect and choose the contract

  1. Open and authenticate TWS or IB Gateway. Keep Read-Only API enabled and check the configured API port. Authentication stays in the provider's application.
  2. In Trader, choose Open Paper / Live broker connections. Select the intended environment and provider, check the port and choose a unique client ID. Live inspection also requires the displayed acknowledgement.
  3. Choose Connect read-only and wait for API readiness. Check the account and environment in TWS itself; a port number does not prove which login is active.
  4. In TWS, open Contract Description for the instrument. Copy its contract ID and exchange into the quote inspector. The contract ID identifies the exact security, including its asset and expiry where relevant. A ticker alone can be ambiguous.
  5. Choose Subscribe to quote. The inspector requests ordinary streaming subscribed data. It does not request a regulatory snapshot or automatically switch to a paid service. API market-data permissions still depend on the provider session. See IBKR's market-data workflow.
  6. Read the bid, ask, last price and their sizes. Each value shows its reported data type and local receipt age. Waiting means no supported observation has arrived for that field.
  7. Choose Cancel quote stream before inspecting another contract. Cancellation stops market data only. It cannot cancel an order. Disconnecting or closing the window closes the socket.

Understand the evidence

LabelMeaning
Real-timeThe provider reported the real-time data type. This is still a received observation, not a guarantee of an executable price.
Frozen, delayed, delayed frozenThese provider types remain visible and are never silently relabelled real-time. The inspector requests subscribed real-time data; it does not enable a delayed fallback itself.
UnconfirmedThe provider type has not been established. The observation remains stale until a compatible newly received value establishes its type.
STALEThe value is more than 15 seconds old, missing, unavailable, associated with another data type, cancelled, failed or disconnected. An unchanged market can produce no new tick; the label describes observation age.
UnavailableThe provider sent a missing-value sentinel. It is not presented as a usable price. A negative price with a nonzero size remains an observation.

Receipt time is measured on this computer. It is not an exchange timestamp. Bid and ask arrive independently: a new ask does not make an old bid fresh. Decimal text is retained without converting it into rounded binary money.

If no quote arrives

Check the exact contract ID and exchange, market hours, the TWS login and its API market-data permissions. A quote-specific refusal appears in the quote panel while account observations remain available. Cancel the failed subscription and correct the cause before trying again. Global connection failures require reconnecting.

The current native C connection negotiates the legacy framed protocol supported by the component; it does not decode the newer protobuf protocol. Authenticated provider compatibility and subscribed-data behaviour need local acceptance. The inspector currently shows one contract; Framework can own up to 16 subscriptions for future watchlist consumers. There is no contract search, historical candle loading, automatic rerouting, chart feed or order transmission in this inspector.

IBKR explains contract identity in Defining contracts. Use the provider's actual contract description rather than a sample identifier from a tutorial.
