Watchlists and reviewed orders in Umicom Trader

The Broker trading page uses Umicom Framework for instrument lookup, market observations and order handling. The separate Umicom Demo page is a simulator. Its prices, positions and funds do not represent a broker account.

The reviewed-order feature is experimental and requires qualification with a paper account before relying on it. A successful local submission only queues a request: the broker must still accept it. This guide describes the implemented controls, not a claim of completed broker certification.

1. Open your broker connection

  1. Choose Paper or Live on Trader's welcome screen. Confirm the same mode in IB Gateway or TWS. Enter your username, password and authentication approval in that broker application.
  2. Use Refresh installations to check common installation locations. For a custom installation, enter the complete executable path and explicitly choose Open IB Gateway. Detection is bounded; it does not search every drive. Launching does not sign you in.
  3. In the broker application's API settings, enable socket clients and note the port. The usual IB Gateway ports are 4002 for Paper and 4001 for Live; TWS normally uses 7497 and 7496. Your configured port takes precedence.
  4. Open Connection and account tools from Broker trading. Match the program, port and a positive, unused client ID. Connect and wait for API ready.
  5. Select an account reported by the connection and choose Read account. Wait for both account values and positions to complete.

Read-Only API can remain enabled in Gateway while viewing data. To test order placement in a paper account, explicitly disable the broker's Read-Only API setting. Trader still starts with its own order permission disabled. Changing the Paper/Live selection alone does not grant that permission. The socket protocol does not attest the account mode: verify it in Gateway.

2. Find an instrument

A contract ID identifies one instrument. A symbol may identify several exchanges, currencies or futures expiries, so selecting the exact result matters.

  1. Open Instrument. Choose Shares, Futures or Bonds.
  2. Enter the broker symbol or bond identifier, exchange route and currency. For futures, optionally narrow the expiry using YYYYMM or YYYYMMDD. For example, YYYYMM means four year digits followed by two month digits.
  3. Select Find instruments and wait for a complete response. If there are too many results, narrow the query. No result can also mean that the broker cannot resolve that combination; it is not proof that the instrument does not exist.
  4. Choose the exact result and select Use selected instrument. This fills the Market data identity. Stop an existing quote stream first; a selection never silently replaces its instrument.

Search covers bounded contract descriptions for shares, futures and bonds. Broker permissions and identifiers govern what can be returned. Bond descriptions are available for inspection, but this order ticket does not submit bond orders. Options retain their separate lookup page.

3. Create and save a watchlist

  1. Select an instrument as above. Open Watchlist.
  2. Enter a watchlist name and an instrument label, then choose Add selected instrument. Identity is the contract ID plus exchange route. Repeating the same identity does not create a second row.
  3. Repeat for further instruments. One list holds at most 64 entries. Select a row and choose Remove selected row to remove it from the in-memory list.
  4. Enter a complete local file path, such as C:\umicom\_local\watchlists\paper.ini. Create the parent folder first. Choose Save; this replaces the named file using consistent local replacement. No credentials are included.
  5. To restore a saved list, enter its path and choose Open. Invalid or oversized files leave your current list intact.
  6. Select a row and choose Use instrument, then explicitly start quotes in Market data.

Saving is explicit. Unsaved edits are lost when the workspace closes. This first watchlist stores instrument selections; it is not yet a grid streaming many simultaneous quotes.

4. View portfolio, balances and P&L

Account and positions shows broker account values and the reported position quantity and average cost. The account values include the broker's available balance, cash and account-value tags. Preserve their currency labels: cash, buying power and net liquidation value are different measures.

These tables are point-in-time reports. Choose Refresh account to read them again after activity. An incomplete table is not a zero balance. Refreshing clears order permission, requiring a new explicit enable/review sequence.

Open Profit and loss, choose an advertised account and start the desired account or instrument stream. P&L means profit and loss. Daily, realised and unrealised values retain the provider's availability and reporting semantics. Missing values are not zero. Market data subscriptions and broker permissions may differ between Live and Paper.

5. Prepare and submit a reviewed limit order

A limit order sets a maximum purchase price or minimum sale price. DAY makes the order valid for the trading day under the broker's rules. The current ticket uses regular trading hours, integer quantities and shares or futures only.

  1. Refresh the account so both completed responses are less than 60 seconds old.
  2. Open Order ticket. Verify the account and actual Gateway mode, select the confirmation checkbox and choose Enable order entry. This authority is limited to that connection and account.
  3. Enter the exact contract ID and route, Buy or Sell, quantity and positive limit price. Select Read instrument and wait for exactly one fresh description.
  4. If the description advertises a price rule for that route, choose Read price rules and wait for it. Prices must match the broker's tick size and applicable price band. Quantity must meet the reported size rules.
  5. Choose Review order. Read the account, mode, instrument, expiry, currency, side, quantity, price and route.
  6. Choose Submit reviewed order only if those details match your intention. The review expires after 30 seconds; editing any field requires a new review. Submission consumes the review once.
  7. Observe the returned order ID and broker status. Check Open orders and Trades for independent broker observations. A rejection message means the broker did not accept the request; queued is not filled.

Read only disables new submissions. It does not withdraw orders already sent to the broker. To request cancellation, enter an order ID submitted by this session and choose Cancel submitted order. An order can still fill while cancellation is pending. The control does not cancel unrelated clients' orders.

6. Start a ticket from a chart or ladder

On Chart, the Buy/Sell ticket controls copy the selected broker instrument and last observed close into Order ticket. On Market depth, choose Buy at ask… or Sell at bid… at the displayed level. These actions require recent observations and prepare a limit ticket; they do not submit an order. Continue with metadata, price-rule and account review.

Chart drawings and a complete drag-to-place order overlay are not implemented by these controls. The depth table is not a guarantee of available liquidity or execution price.

Recovery and current limits

  • Disconnected or uncertain: inspect orders directly in Gateway before attempting another order. There is no automatic resubmission.
  • Uncertain orders block new execution in the retained connection owner until a matching broker identity reconciles them. A status alone does not establish the account and instrument.
  • Submission tracking is in memory, with a maximum of 32 orders per connection owner. Closing/recreating the owner or restarting Trader loses this local tracking. Reconcile in Gateway first; do not retry because the local list is empty.
  • Orders currently support the negotiated socket protocol range 164–176. Unsupported protocol or instrument combinations are refused.
  • Market, stop, bracket, fractional, options, bond execution, order modification, persistent execution recovery and margin previews remain outside this ticket.
  • Guest uses simulation. To use the full broker ticket, open a Paper or Live session; the guest inspector is a separate observation route.
  • No successful native build, GUI exercise or broker order test is implied by this guide. Use paper qualification and review provider responses before live use.
